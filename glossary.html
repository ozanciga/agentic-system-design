Glossary

One plain definition per term. In lessons, the first use of a term is underlined; hover to see its definition, or click to come here.

A/B test
Randomly splitting live traffic between two versions and comparing their outcomes. Explained in: Compare designs fairly
A2A
Agent2Agent: a protocol for independent agents to send each other tasks and report status and results. Explained in: MCP vs. A2A, and agent-to-agent messages
ACL
Access control list: the users or groups allowed to read a document. Explained in: Filter by permission before the model sees text
agent-as-tool
Calling another agent like a tool: it returns a result and the caller keeps control. Explained in: Handoffs, agents as tools, and peer-to-peer
agentic workflow
A fixed sequence of steps written in code, where some steps call a model. Code, not the model, decides the path. Explained in: Decide whether you need an agent
approximate nearest-neighbor
A fast vector-search method that finds very close matches without comparing against every stored vector. Explained in: Split and index documents
at-least-once delivery
A delivery guarantee where every message arrives, but some may arrive more than once. Explained in: Idempotency: retry without repeating an action
atomic
Done as one indivisible step: it either fully happens or not at all, and nothing can slip in between. Explained in: Design tools and check their inputs
audit trail
An append-only record of who asked for what, what was decided, and what actually happened. Explained in: Audit trails without leaking data
blast radius
How much damage one mistake can do: how much money, how many records, how many people. Explained in: Set autonomy per action
BM25
The standard keyword-search scoring method: it ranks documents by how often the query's words appear in them. Explained in: Hybrid search and reranking
canary
Releasing a new version to a small share of real traffic first, and expanding only if it performs well. Explained in: Release gates and canary releases
chaos testing
Deliberately causing failures in a realistic environment to check that the system stays correct. Explained in: Failure injection and chaos testing
checkpoint
A saved record of a task's progress, from which it can resume. Explained in: Conversation, task state, and memory
chunk
A piece of a document, such as a section or paragraph, indexed and retrieved on its own. Explained in: Split and index documents
circuit breaker
A switch that stops calling a failing dependency for a while, instead of waiting on it again and again. Explained in: Provider outages and graceful degradation
Cohen's kappa
An agreement score between two raters that corrects for agreement by chance: 1 is perfect, 0 is no better than chance. Explained in: LLM-as-a-judge
compare-and-swap
Update a record only if it still has the version you read; otherwise the write fails and you re-read. Explained in: What to save to memory
compensation
A new action that offsets an earlier one, such as cancelling a booking. Unlike a rollback, it can cost fees and leave traces. Explained in: Sagas: undo partly finished actions
context engineering
Choosing what information goes into each model call, and how it is labeled. Explained in: Build the model's context
context window
The maximum amount of text, measured in tokens, that a model can read in one call. Explained in: Fit the context window
control plane
The part of a platform that manages configuration: versions, permissions, routing, and rollouts. Explained in: Shared platform and team ownership
critical path
The longest chain of steps that must happen one after another; it sets the total time. Explained in: Latency and the critical path
data plane
The part of a platform that runs the actual tasks, using configuration from the control plane. Explained in: Shared platform and team ownership
data residency
Rules about which countries or regions data may be stored or processed in. Explained in: Keep secrets and data from leaking
dead-letter queue
A holding area for tasks that keep failing, kept aside with their context for a person to handle. Explained in: Retries and dead-letter queues
deterministic
Always producing the same output for the same input. Plain code is deterministic; model calls are not. Explained in: The model proposes; code decides
durable execution
Running a workflow so that each step's result is saved and the workflow can resume after a crash. Explained in: Durable execution: survive crashes
durable store
Storage that survives crashes and restarts, such as a database. Anything kept only in a program's memory is lost when it stops. Explained in: The parts of a production agent
egress
Outbound network traffic. An egress allowlist names the only destinations a system may contact. Explained in: Keep secrets and data from leaking
embedding
A list of numbers that represents a text's meaning. Texts with similar meaning get similar embeddings. Explained in: Hybrid search and reranking
error budget
The amount of failure an SLO allows in its window, such as 0.1% for a 99.9% target. Explained in: SLOs and what to do when they're missed
evaluator–optimizer
A pattern where one step produces output, another scores it against a rubric, and the first revises until it passes. Explained in: Generate, check, and revise
exponential backoff
Waiting longer after each failed attempt (for example 1 s, 2 s, 4 s) before trying again. Explained in: Retries and dead-letter queues
fan-out
Starting several independent sub-tasks at once and collecting their results. Explained in: Run work in parallel safely
fencing token
A number that increases with every new claim on a task. Storage rejects writes carrying an older number. Explained in: Stop stale workers with fencing tokens
golden set
A versioned set of realistic test tasks, each with a known starting state and expected outcome. Explained in: Build a golden test set
graceful degradation
Continuing to provide the parts of a service that still work when a dependency fails, and saying clearly what doesn't. Explained in: Provider outages and graceful degradation
grounded
Based on supplied evidence rather than on the model's memory. Explained in: How RAG works
hallucination
A confident statement from a model that no source or fact supports. Explained in: Verify before claiming success
handoff
Passing a conversation or task to another agent or to a person, who then takes it over. Explained in: Handoffs, agents as tools, and peer-to-peer
hedged request
Sending a duplicate of a slow read to another server and using whichever reply arrives first. Explained in: Latency and the critical path
held-out set
Test cases kept aside and never used while tuning, so scores on them stay honest. Explained in: Build a golden test set
human-in-the-loop
A design where a person reviews or approves certain actions before they run. Explained in: Set autonomy per action
hybrid search
Running keyword search and vector search together and merging their results. Explained in: Hybrid search and reranking
idempotent
An operation is idempotent if doing it twice has the same effect as doing it once. Explained in: Idempotency: retry without repeating an action
invariant
A rule that must always hold, such as “an order is never refunded more than its total”. Explained in: Build a golden test set
jitter
Random variation added to retry delays, so many clients don't all retry at the same moment. Explained in: Retries and dead-letter queues
kill switch
A control, outside the model, that immediately stops a capability or workflow from taking new actions. Explained in: Kill switches and incident response
latency
How long something takes, from request to result. Explained in: Latency and the critical path
lease
A time-limited claim on a task. If the holder doesn't renew it, another worker may take over. Explained in: Stop stale workers with fencing tokens
least privilege
Giving each component only the permissions its current task needs, and no more. Explained in: Least privilege and tenant isolation
Little's law
Average items in a system = arrival rate × average time each spends in it. Explained in: Scaling and capacity planning
LLM-as-a-judge
Using a language model to score outputs against a rubric. Explained in: LLM-as-a-judge
McNemar's test
A statistical test of whether two systems' pass/fail results on the same cases differ by more than chance. Explained in: Compare designs fairly
MCP
Model Context Protocol: a standard way for AI applications to connect to tools and data exposed by MCP servers. Explained in: MCP and third-party integrations
memory poisoning
Untrusted content or a wrong guess saved to long-term memory as if it were a trusted fact. Explained in: What to save to memory
microVM
A very small, fast-starting virtual machine. It isolates code more strongly than a container. Explained in: Run generated code in a sandbox
mTLS
Mutual TLS: both sides of a connection prove who they are with certificates. Explained in: MCP vs. A2A, and agent-to-agent messages
multi-hop retrieval
Retrieval in several rounds, where each search uses what the previous one found. Explained in: Multi-hop retrieval
operation ID
A unique ID for one intended action, sent with every attempt, so the receiving service can spot repeats and apply the action only once. Explained in: Idempotency: retry without repeating an action
orchestrator
The program that runs the agent loop: it calls the model, sends tool calls for checking, saves progress, and enforces limits. Explained in: The parts of a production agent
orchestrator–worker
A pattern where one agent splits a task, assigns parts to worker agents, checks their results, and combines them. Explained in: The supervisor pattern
p95
Percentile latency: p95 is the time that 95% of requests finish within. It shows the slow tail that averages hide. Explained in: Latency and the critical path
plan-and-execute
A pattern where the model first writes a list of steps, then the steps are executed one at a time. Explained in: Plan, then replan on new evidence
policy engine
A component that evaluates rules kept as data (not in prompts) and answers allow, deny, or needs approval. Explained in: The model proposes; code decides
precision@k
Of the top k retrieved passages, the fraction that are relevant. Explained in: Evaluate retrieval on its own
prompt caching
A provider feature that reuses the processed form of a repeated prompt prefix, cutting cost and latency. Explained in: Fit the context window
prompt chaining
Running model calls in a fixed order, where each step uses the checked output of the previous one. Explained in: Choose an orchestration pattern
prompt injection
Text hidden in data (a web page, email, or tool result) that tries to give the model new instructions. Explained in: Prompt injection
provenance
Where a piece of information came from, and how it was verified. Explained in: What to save to memory
RAG
Retrieval-augmented generation: fetch relevant documents at request time and give them to the model, so answers rely on sources. Explained in: How RAG works
rate limit
A provider's cap on requests or tokens per minute. Exceeding it returns errors such as HTTP 429. Explained in: Rate limits and fair scheduling
recall@k
Of all relevant passages, the fraction that appear in the top k results. Explained in: Evaluate retrieval on its own
reciprocal rank fusion
A way to merge ranked lists: each document scores the sum of 1 / (60 + its rank) across the lists it appears in. Explained in: Hybrid search and reranking
reconcile
After an unclear result such as a timeout, look up what actually happened in the system that owns the data, before doing anything else. Explained in: Idempotency: retry without repeating an action
reranker
A model that reads the query and each candidate passage together and re-orders the candidates by relevance. Explained in: Hybrid search and reranking
row-level security
A database feature that automatically filters rows by the current user or tenant. Explained in: Least privilege and tenant isolation
RPO
Recovery point objective: how much recent data you can afford to lose in a failover, measured in time. Explained in: Multi-region failover
RTO
Recovery time objective: how long recovery may take before service must be back. Explained in: Multi-region failover
rubric
A fixed list of criteria used to score an output. Explained in: Generate, check, and revise
saga
A multi-step action across services where each step has a matching “undo” action, run if a later step fails. Explained in: Sagas: undo partly finished actions
sandbox
An isolated environment that limits what running code can reach: files, network, CPU, memory, and time. Explained in: Run generated code in a sandbox
schema
A formal description of a data shape: which fields exist, their types, and which are required. Explained in: Get typed decisions from the model
semantic layer
Documented, shared definitions of business metrics (such as “revenue”) that queries can look up. Explained in: Case study: answering questions from a database
shadow mode
Running a new version on copies of real requests without letting it take real actions, to compare it with the current one. Explained in: Release gates and canary releases
shard
To split an index or database into parts, each holding a subset of the data, such as one tenant or region. Explained in: Split and index documents
side effect
A change to the outside world, such as moving money, sending an email, or updating a record. Explained in: Send every action through a tool gateway
SLO
Service-level objective: a target for a measured property, such as “95% of replies within 8 s over 28 days”. Explained in: SLOs and what to do when they're missed
span
One timed step inside a trace, such as a single model call or tool call. Explained in: Logs, metrics, and traces
structured output
A model API feature that makes the response follow a given schema. Explained in: Get typed decisions from the model
tail latency
The latency of the slowest requests, such as the slowest 5% or 1%. Explained in: Latency and the critical path
task contract
A written statement of a task's goal, allowed actions, limits, and what counts as done. Explained in: Define the task and what counts as done
tenant
One customer organization on a shared system. Each tenant's data must be invisible to the others. Explained in: Least privilege and tenant isolation
token exchange
An OAuth flow that swaps a user's token for a narrower, short-lived token naming both the user and the agent acting for them. Explained in: Least privilege and tenant isolation
tombstone
A marker recording that something was deleted, so stale copies or jobs can't bring it back. Explained in: Expire and delete memories
tool gateway
The single service every tool call passes through. It checks identity, permissions, and approvals, and logs each call. Explained in: Send every action through a tool gateway
trajectory
The full sequence of decisions and tool calls an agent made during one task. Explained in: Evaluate the whole run, not just the answer
TTL
Time to live: how long a cached item stays valid before it expires. Explained in: Caching safely
vector search
Search that finds passages whose embeddings are close to the query's, so it matches meaning rather than exact words. Explained in: Hybrid search and reranking
worker
A running program that picks up tasks and executes their steps. Workers can be replaced; the task's saved state cannot. Explained in: Conversation, task state, and memory
